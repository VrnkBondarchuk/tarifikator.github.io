# Тарификатор: промостраница и форма демодоступа

Страница и API работают на Node.js 22.13+ без сторонних пакетов. Сервер хранит заявки в SQLite (`node:sqlite`), запускает существующий триггерный сценарий Unisender для каждого заявителя и добавляет в маркетинговый список только адреса с отмеченным чекбоксом. Просмотр заявок: `/admin`.

## Передача разработчику и размещение

Для формы нужен Node-хостинг с постоянным каталогом для SQLite, HTTPS и доступом сервера к URL API-триггера Unisender и `api.unisender.com`. Разработчику нужно запустить **один** процесс `node server.mjs` и направить запросы сайта и `/api/*` на него через HTTPS. Не размещайте `data/`, `.env` и `server.mjs` в открытом каталоге статического веб-сервера. `PUBLIC_ORIGIN` должен точно совпадать с адресом сайта, например `https://example.ru` (без завершающего `/`).

Задайте на сервере переменные окружения из `.env.example`. Файл `.env` сервер автоматически не читает. `npm install` не нужен. Запуск: `npm start`. Для хранения заявок настройте резервное копирование каталога `DATA_DIR` вместе с SQLite WAL-файлами. Останавливайте процесс перед переносом базы. Каталог должен быть доступен только пользователю сервера. Возможность запуска Node и постоянного хранилища на выбранном размещении проверяет разработчик.

Для локальной проверки нужен тот же набор переменных окружения, `PUBLIC_ORIGIN=http://localhost:3000` и тестовые данные Unisender. В продакшене используйте отдельный длинный случайный пароль администратора. Админка применяет HTTP Basic Auth; доступ к ней должен идти только через HTTPS. Уведомления команде не отправляются.

## Что настроить владельцу Unisender

1. В блоке «API-триггер 1» существующего сценария скопировать сгенерированный URL и задать его на сервере как `UNISENDER_TRIGGER_URL`. URL не нужен в чате, HTML или Git. В шаблоне входящего запроса сопоставить `email` с `{{email}}`, соединить триггер с блоком Email и запустить сценарий. Сервер отправляет на URL JSON `{"email":"..."}`; ответ `{"success":true}` означает, что запуск принят.
2. Проверить в блоке Email тему, проверенного отправителя, ссылку и общие данные демодоступа. Содержание письма остаётся в сценарии Unisender, не в коде сайта.
3. Задать ID маркетингового списка `37` как `UNISENDER_MARKETING_LIST_ID`. Отмеченный чекбокс вызывает `subscribe` с `double_optin=3`; он не отправляет письмо подтверждения. Перед подпиской сервер проверяет `getContact` и пропускает адрес, который уже отписался или заблокирован. Перед запуском дополнительно проверьте поведение на тестовом ранее отписавшемся адресе в вашем аккаунте.
4. Для подписки создать API-ключ и передать его разработчику **через защищённое хранилище секретов**, чтобы тот задал `UNISENDER_API_KEY` на сервере. Ключ не нужен в чате, HTML или Git.

Технический список `36`, созданный ранее, для API-триггера не требуется. Заявки без согласия на рекламу сохраняются в SQLite и видны в `/admin`; сценарий получает их email только для выдачи доступа.

После настройки протестируйте два адреса: без маркетингового чекбокса и с ним. Оба должны получить письмо через сценарий, только второй — появиться в маркетинговом списке. Проверьте тему, HTML, ссылку и общие данные входа в полученном письме. Ответ API-триггера означает запуск сценария, не окончательную доставку.

## Обязательные условия перед публичным запуском

В `index.html` сохранены исходные тексты двух чекбоксов. Первый чекбокс обязателен для отправки и его отметка сохраняется в заявке; маркетинговый остаётся необязательным. Перед публикацией проверьте и утвердите тексты о персональных данных и согласии на рекламу, добавьте действующую ссылку на политику и задайте идентификатор её версии в `CONSENT_VERSION`. Установите срок хранения и порядок удаления заявок. Без этих действий форму не следует публиковать.

Сервер ограничивает повторный запрос на один адрес 60 секундами и короткие запросы с одного сетевого источника. Капчи нет. Очередь повторяет определённые ошибки Unisender до пяти попыток. Если исход вызова API-триггера неизвестен, заявка получает статус `review`: перед повтором сотрудник должен проверить статистику сценария, чтобы избежать второго письма. В админке есть поиск, фильтры, статусы, ручной повтор и CSV. CSV содержит персональные данные, поэтому храните выгрузки с теми же ограничениями доступа.

Полный контракт и критерии приёмки — в `SPEC_DEMO_FORM.md`.
